Building a Complete Personal Harness: LLM Wiki + Developer's Second Brain

Roan Brasil Monteiro · 23 min · 👏 888 · 💬 17

Tutorial paso a paso para montar un vault de Obsidian que funciona como base de conocimiento mantenida por un agente (Claude Code), combinando el patrón LLM Wiki de Karpathy con el "segundo cerebro" de un desarrollador: ADRs, debriefs, proyectos y notas técnicas. La promesa: una tarde de setup y un sistema que corre para siempre. El diseño se organiza en tres zonas con separación física estricta — raw/ (inmutable, solo lo que tú curaste), wiki/ (mantenida por el agente, conceptos/entidades/síntesis) y dev/ (colaborativa: ADRs y debriefs) — más un CLAUDE.md en la raíz que actúa como "cerebro reptiliano" y se lee en cada sesión. La regla de oro: el agente nunca toca lo que curaste; tú rara vez tocas lo que el agente mantiene.

Hay tres vías de conexión. La recomendada es la ruta directa por filesystem con las skills oficiales de Steph Ango (kepano/obsidian-skills, 13.9k+ estrellas, enero 2026): obsidian-markdown (wikilinks, callouts, frontmatter), obsidian-bases, json-canvas, obsidian-cli y defuddle (extracción limpia de URLs). La segunda vía es MCP vía el plugin Local REST API (con un aviso de bug de sobrescritura de archivos en v3.6.x), y la tercera es el plugin preempaquetado claude-obsidian. El autor crea dos skills custom — adr-writing (formato MADR, numeración ADR-NNNN, ADR aceptado = inmutable) y debrief-writing (post-mortem blameless con "generalizable learning") — y dos slash commands: /wiki-ingest (presenta un plan antes de escribir) y /wiki-query (sintetiza respuestas citando wikilinks y distinguiendo inferencias).

La parte de seguridad es central: versionar el vault con git como red de seguridad, declarar allowed-tools en cada comando como capa de defensa (sin rm en la lista blanca), y defensa en profundidad contra prompt injection vía fuentes externas (CLAUDE.md prohíbe borrar, el plan previo expone intenciones destructivas, y git revierte). El coste típico de un vault de 200–500 notas es de $20–50/mes en tokens. El cierre argumenta que esto no es "una herramienta de productividad" sino infraestructura de conocimiento que acumula valor monotónico: el artículo 30 conecta con 5 previos, el 100 con 30, y en uno o dos años el vault se vuelve un activo cognitivo que ningún chatbot sin estado puede replicar.

How to Create Loops with Claude Code: A Practical Guide to Agentic Automation

Youssef Hosni · Level Up Coding · 63 min · 👏 1.3K · 💬 28

La tesis es que para trabajo repetitivo, con estado o que exige varias rondas de comprobación, la mejor abstracción no es un mejor prompt sino un "loop": un workflow repetible alrededor del modelo con seis partes — trigger, contexto, acción, verificación, estado y decisión. Claude sigue siendo el motor de razonamiento, pero el loop aporta la estructura operativa. Como las sesiones de Claude son efímeras, el loop necesita estado persistente fuera del modelo (un archivo PROGRESS.md). Antes de construir nada, propone un "Loop Readiness Check" de cinco preguntas: ¿se repite la tarea? ¿es verificable el resultado? ¿tiene Claude contexto suficiente? ¿hay condición de parada clara? ¿hay un punto de revisión humano seguro?

El loop mínimo viable usa cuatro archivos: TASK.md (objetivo estable), PROGRESS.md (memoria entre runs), LOOP_INSTRUCTIONS.md (procedimiento y reglas de seguridad) y una carpeta outputs/. La clave es una "escalera de permisos" de seis niveles — de análisis read-only a acción automatizada de bajo riesgo — y empezar siempre en los niveles 1–2 (read-heavy, write-light). La verificación debe separar al "trabajador" del "revisor", exigir un veredicto PASS/FAIL sin crédito parcial, y definir qué pasa al fallar (reintentar, escalar o parar) con límite de iteraciones. Para código, la verificación reutiliza la infraestructura existente: npm test, linters y builds, que fallan sin que Claude decida subjetivamente.

La programación llega con /loop <intervalo>, que solo repite el prompt en una cadencia; la calidad sigue viniendo de la estructura. Distingue /loop (recurrencia por tiempo) de /goal (continuar hasta una condición verificable). Un loop programado necesita política de parada y dos modos de salida: "quieto" (nada cambió, actualiza y para) y "atención" (algo falló, reporta con claridad). Antes de programar, corre el loop manualmente 3–5 veces y aplica una "ventana de revisión" de una semana, midiendo outputs útiles, falsas alarmas y problemas no detectados. El patrón final es siempre el mismo: Trigger → Contexto → Acción → Verificación → Estado → Revisión; lo que cambia con el tiempo son las herramientas y los permisos, no la arquitectura.

How I Cut Claude Code Token Usage by 90%+ With 5 Tools, Custom Hooks

Abid Abdul Gafoor · 16 min · 👏 456 · 💬 11

El autor arranca cuantificando el problema: cargo test con 262 tests consume 4.823 tokens, git diff HEAD~1 21.500, y leer un archivo de 500 líneas llena la ventana rápido. Su solución son cinco capas apiladas, cada una en un punto distinto del pipeline. Capa 1 — Codebase Memory MCP (CBM): indexa el codebase en un grafo de conocimiento vía tree-sitter (66 lenguajes); cinco consultas estructurales costaron ~3.400 tokens frente a ~412.000 explorando archivo a archivo (99,2% de ahorro). Capa 2 — context-mode: sandboxea outputs grandes y devuelve solo un resumen, con el contenido completo indexado en BM25 para búsqueda bajo demanda. Capa 3 — RTK (Rust Token Killer): binario Rust que comprime la salida de CLI en el sitio (60–90%). Capa 4 — Headroom: proxy entre Claude Code y la API de Anthropic que comprime todo el prompt saliente (historial, system prompts, CLAUDE.md), con CodeCompressor AST-aware y CacheAligner para estabilizar el prefijo del KV-cache. Capa 5 — Caveman: plugin que hace hablar menos a Claude (50–75%).

El mensaje central es que no basta con sugerir eficiencia: hay que forzarla con hooks. Dos hooks hacen el trabajo pesado — bash-ban-raw-tools (bloquea cat/grep/find/rg para que el output crudo no salte la compresión) y cbm-code-discovery-gate (bloquea Read/Grep sobre código fuente hasta que CBM se ha usado una vez) — además de escáneres de rechazo PostToolUse (regla ESLint custom, regex en Node, plugin del analyzer de Dart, Husky + lint-staged). La configuración usa claude-opus-4-7 con effortLevel: xhigh, CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50 (compacta al 50% en vez del 95%), ENABLE_PROMPT_CACHING_1H=1 (extiende el TTL del cache de 5 min a 1 hora) y subagentes en claude-sonnet-4-6 (60% más barato que Opus). El ecosistema incluye 21 agentes especialistas y comandos /unleash (swarm de revisión paralela) y /e2e.

Los resultados: sesiones de ~30 minutos a más de 3 horas en la misma ventana de 200K, tokens de exploración de código de ~400K a ~3,4K, y un pipeline multi-modelo (Opus planifica e implementa, Codex/GPT revisa en cross-vendor, Sonnet para subagentes). Es explícito sobre los riesgos: es un setup power-user que reduce los checkpoints humanos de permisos, tira de dependencias de terceros (PyPI, npm, marketplaces), y estas herramientas pueden ver prompts, código y secretos — recomienda auditar, pinear dependencias y, si algo incomoda, instalar manualmente. La frase de cierre resume la filosofía: "No le digas a Claude que sea eficiente. Fórzalo. Un hook que bloquea un patrón derrochador vale más que 1.000 palabras de CLAUDE.md".

AI Images Looks Perfect. Until You Notice This.

HalfJourney Lab · 11 min · 👏 1.4K · 💬 33

La tesis es elegante: a este nivel de calidad ya casi no hay errores visibles en las imágenes generadas; lo que queda es algo más sutil — "efectos sin causa". Una cámara registra las consecuencias de causas reales (esa sombra viene de ese objeto, ese reflejo de esa ventana); un modelo generativo aprende qué aspecto tienen las cosas, no cómo funcionan, así que pinta el reflejo o la sombra "donde queda bonito" sin la física que los obliga a estar donde están. La frase que hay que recordar: la IA no entiende causa y efecto, entiende correlación. Ese es el "tell" de 2026.

Ilustra cinco casos, del más obvio al mejor escondido. (1) El ojo miente primero: una estrella de luz "esculpida" dentro del iris, una capa por debajo de donde el reflejo debería vivir en la córnea. (2) El catchlight es prueba de dónde estaba la luz: un selfie nocturno de brazo extendido con una luz de flash propia de una DSLR con 50mm — la cámara no cabe en la mano que finge sostenerla. (3) La sombra huérfana: una sombra en la camiseta sin cuerpo que la proyecte, porque la luz del sujeto y la del entorno se generaron por separado — "una sola luz ilumina la escena; cuando hay dos lógicas de luz, hay dos fotos". (4) El blur plano: un fondo desenfocado sin gradiente de profundidad (todo a la misma distancia), como una imagen emborronada en Photoshop pegada detrás. (5) Gafas sin lentes: sin puente, sin patilla, sin reflejo — reproducen la apariencia del objeto sin su función.

De ahí sale una ley de cuatro letras para revisar cualquier imagen: ISLP — Iris (redondo, y lee su reflejo), Skin (poros reales, no uniformidad limpia), Light and shadow (una sola lógica de luz), Physics (blur gradual, ópticas coherentes). Un consejo de prompting: declara la causa, no el efecto — escribe "iPhone con flash y gran angular" o "DSLR con flash frontal, 50mm" en lugar de "luz dramática", para arrastrar millones de imágenes reales asociadas y "acorralar" al modelo dejándole menos espacio para inventar imposibilidades. Aplica a Midjourney, Nano Banana, GPT Image y Reve por igual, porque no es un defecto de una herramienta sino la naturaleza de todo generador de imágenes: los detalles cambian, el pecado no.

What Happens When a Happy Person Takes Ayahuasca?

Alexandre Porto · Cabbanis · 7 min · 👏 2.1K · 💬 18

El autor resume un estudio realizado por economistas (no psicoterapeutas ni neurocientíficos, como es habitual) en un centro de ceremonias de ayahuasca en una zona urbana de Brasil, que recibe unas 1.400 personas al año sin psiquiatra presente. De 429 inscritos, 252 participaron en la comparación principal, lo que lo convierte en el mayor ensayo controlado aleatorizado con psicodélicos jamás realizado. La mitad tomó 9 mg de DMT (50 ml hombres, 40 ml mujeres, con posibilidad de segunda dosis que pidió el 80%); la otra mitad un placebo que no los engañó — solo el 9% creyó haber tomado la bebida activa, una debilidad declarada del estudio.

Los hallazgos son sorprendentes. Tres días después, 1 de cada 3 lo describió como "la experiencia más significativa de mi vida", 4 de cada 10 lo situaron en su top 5, y el 42% de quienes antes consideraban ser padres como lo más importante cambiaron de opinión tras la ceremonia. Hasta seis meses después, quienes tomaron ayahuasca mostraron más felicidad y menos angustia. Pero el hallazgo clave: los beneficios se concentran en quienes llegaron sufriendo; los que ya estaban felices y sin angustia casi no mostraron beneficio al final. "¿Qué le pasa a una persona sana y feliz que toma ayahuasca? Aparentemente… casi nada duradero." También destacó que los mayores de 33 años mejoraron mucho más que los jóvenes — lo contrario de lo que ocurre con los métodos tradicionales —, consistente con la hipótesis de que los psicodélicos reabren "periodos críticos" de plasticidad que se cierran con la edad.

El ritual importa tanto como la molécula: algunos participantes del grupo placebo tuvieron experiencias místicas (sobre todo quienes ya meditaban), con beneficios comparables a los de la sustancia; la ventaja del psicodélico es facilitar esas experiencias de forma mucho más fiable. En efectos secundarios, dos de cada tres vomitaron (la "purga" tradicional), 1 de cada 4 lo encontró desafiante y 1 de cada 8 tuvo un "mal viaje", sin señales de daño a los seis meses. Los economistas estimaron que una ceremonia de $24 produce beneficios valorados en $4.608 (ratio 192:1), aunque el propio autor advierte que no hay que tomar ese número en serio. La conclusión: no es una cura universal ni una receta de felicidad, sino una intervención que parece ayudar más a quien se siente atascado, y la evidencia lleva la ciencia psicodélica al mundo real que las comunidades tradicionales ya entendían hace tiempo.

5 "Productivity Tips" That Don't Work for ADHD (And What Actually Does)

No lo es. Desmonta cinco mitos y propone lo que sí funciona. Mito 1, "escribe una lista": la lista asume que lo difícil es recordar, pero para el ADHD lo difícil es empezar, y una lista de tareas vagas ("terminar informe") es solo un muro para sentirse mal — la alternativa es descomponer cada tarea en un siguiente paso que se pueda empezar en menos de diez minutos.

Mito 2, "usa fuerza de voluntad": la atención ADHD funciona en ráfagas, no bajo demanda; forzar el foco sostenido quema rápido — la alternativa son sesiones de foco con tiempo acotado (estilo Pomodoro). Mito 3, "organiza tus pensamientos antes de empezar": las herramientas de planificación esperan que llegues con la cabeza ordenada, justo cuando no puedes — la alternativa es un "brain dump" donde volcar todo desordenado y que el sistema lo ordene. Mito 4, "prioriza por importancia": el cerebro ADHD no procesa "importante" igual; lo urgente-pequeño eclipsa lo importante-lejano — la alternativa es priorizar por la urgencia tal como el cerebro la experimenta. Mito 5, "recompénsate al terminar todo": esperar al final para reconocer el progreso deja la mayor parte del esfuerzo sin feedback — la alternativa es reconocer las pequeñas victorias (racha, minutos de foco).
